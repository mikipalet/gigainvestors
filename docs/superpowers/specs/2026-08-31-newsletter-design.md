# Quarterly newsletter — design

One email per quarter, sent automatically when the new 13F quarter is essentially complete. Beautiful (house style), free, with public analytics.

## Decisions (approved 2026-08-31)

- Cadence: one issue per quarter (option 1), not rolling digests.
- Provider: Resend (Vercel marketplace), free tier: 3,000/month, 100/day, audiences + broadcasts + webhooks. Daily cap handled by scheduled batching.
- Analytics store: Redis (Vercel marketplace, free tier) for webhook counters and rate limits.
- Automation: GitHub Actions on the public repo (daily sync + conditional send + commit + deploy). No Vercel crons.
- Sender: `letters@gigainvestors.com`; reply-to `hello@gigainvestors.com`. DNS records created via Vercel domains API.
- Double opt-in. Unsubscribe via Resend's link. Nothing stored outside Resend and Redis counters.
- Cost target: $0.

## Surfaces

### `/newsletter` (static page + client form)
Paper page: one line, one input, one button. Below: issue archive (cards: quarter, headline moves, open rate) and the public stats block (subscribers, per-issue delivered/open/click rates as ink bars). Entry points: bottom bar link `quarterly by email`, About, 404, Munger page.

### `/newsletter/[issue]` (static archive pages)
The exact HTML of each sent issue, rendered in-site. Also the answer to "when was the data last updated": the newest issue is the newest quarter.

### API routes (Vercel functions, Node runtime)
- `POST /api/subscribe` — Zod body `{ email, hp }` (honeypot must be empty). Rate limit 5/hour/IP in Redis. Creates Resend contact in audience `AUDIENCE_ID` with `unsubscribed: true`, sends confirmation email with an HMAC-signed link (`CRON_SECRET` as key, 48h expiry). Always responds 200 with a neutral message (no email enumeration).
- `GET /api/confirm?t=` — verifies token, sets contact `unsubscribed: false`, redirects to `/newsletter?confirmed=1`.
- `POST /api/resend-webhook` — verifies Svix signature (`RESEND_WEBHOOK_SECRET`); increments Redis hash `issue:{broadcastId}` fields `delivered|opened|clicked|bounced|complained|unsubscribed`; opens/clicks deduped per email via a Redis set with 90-day TTL. Ignores events for non-issue emails.
- `GET /api/newsletter-stats` — `force-dynamic`, `Cache-Control: s-maxage=300`. Returns subscriber count (Resend audience contacts, filtered subscribed) and per-issue counters from Redis. Consumed by `/newsletter`.

### Issue generation (`scripts/newsletter/`)
- `build-issue.ts {quarter}` → derives from `data/store`: consensus most bought / most sold (by holder count), six biggest $ moves (new/add/reduce/sold weighted by dollars), new entrants and exits, per-investor filed count. Renders React Email (`emails/QuarterIssue.tsx`) to HTML + plain text; writes `data/newsletter/{quarter}.json` (manifest: subject, preview, stats inputs) and `public/newsletter/{quarter}.html`. Faces as PNG at `public/faces/png/{slug}-160.png` generated by `scripts/build-faces.ts` (email-safe).
- `send-issue.ts {quarter}` → creates Resend broadcast from the HTML, sends to audience. If subscribed contacts > 100, schedules segments of 100 at 24h intervals (Resend `scheduled_at`). Records `{ broadcastId, sentAt }` into the manifest. Refuses if manifest already has `sentAt`.

### Automation (`.github/workflows/sync.yml`)
Daily 07:00 UTC: `npm run sync` (incremental, change-driven). If anything changed: build faces if needed, commit `data/store`, push (Vercel deploys from GitHub). Then `newsletter:maybe-send`: newest quarter Q; if `filed(Q) / 83 >= 0.8` OR (today > deadline(Q) + 3 days AND filed(Q) >= 40) AND no manifest `sentAt` for Q → build + send + commit manifest and archive page. Secrets: `RESEND_API_KEY`, `RESEND_AUDIENCE_ID` in GitHub Actions secrets (mirrors of Vercel env).

## Email design
Paper background, ink text, Inter fallback stack, 600px single column. Sections: quarter headline + one-line summary; "biggest moves" (face PNG, name, ticker, badge in green/red); "most bought / most sold" two columns with holder counts; "new / gone" list; footer with link to `/?q=` for the quarter, archive link, unsubscribe. No images besides faces and a static PNG of the homepage treemap for the quarter (generated by Playwright in the Action, hosted in `public/newsletter/`).

## Errors
- Resend failures on subscribe: 200 to the client, logged. Confirm with bad token: redirect to `/newsletter?error=link`.
- Webhook signature failure: 401. Redis unavailable: webhook returns 500 so Resend retries.
- Send: any failure leaves no `sentAt`; next day retries. Broadcast creation and send are idempotent via the manifest check.

## Testing
- Unit: issue derivation (consensus, biggest moves, entrants/exits) on fixtures; token sign/verify; batching math.
- Render test: React Email renders without throwing for the latest quarter.
- Manual: send a test issue to one address before enabling automation.

## Out of scope
Segmentation, per-investor alerts, A/B, tracking on the site, paid tiers.
